# Profiles

Profiles are lenses that alter the plan, roles, and closure gates. Combine them deliberately.

## Discovery

**Use for:** open questions, new theories, literature mapping, hidden patterns, competing explanations, experiment design.

**Characteristic flow:**

```text
question → landscape → hypotheses → discriminating tests → surviving model
```

**Required practices:**

- search for prior art and alternative terminology;
- generate competing explanations, not one favored story;
- identify observations that would distinguish them;
- preserve null results and contradictions;
- separate novelty from unfamiliarity.

**Typical closure:** a mapped evidence landscape, a testable hypothesis set, an experiment plan, or a bounded conclusion with uncertainty.

## Delivery

**Use for:** software, documents, events, designs, releases, operational changes, or other defined outputs.

**Characteristic flow:**

```text
outcome → acceptance criteria → milestones → implementation → validation → release
```

**Required practices:**

- define acceptance criteria before building;
- track dependencies and owners;
- test the produced artifact, not merely the plan;
- identify deployment, publication, or merge approval;
- preserve rollback or recovery where relevant.

**Typical closure:** accepted deliverable validated at the required level.

## Audit

**Use for:** engineering review, claim review, compliance checks, evidence inspection, risk discovery, closure matrices.

**Characteristic flow:**

```text
claim set → evidence map → independent challenge → disposition → closure matrix
```

**Required practices:**

- inspect changed files and primary evidence;
- reproduce material calculations where feasible;
- distinguish documented from physically or operationally validated;
- reject closure-by-disposition;
- prioritize blockers by consequence and dependency.

**Typical closure:** a defensible finding set and explicit merge, hold, approve, reject, or investigate recommendation.

## Communications

**Use for:** scientific communication, reports, outreach, announcements, education, public explanation, executive updates.

**Characteristic flow:**

```text
verified facts → audience model → narrative → artifact → accuracy review → publication
```

**Required practices:**

- maintain a source-of-truth ledger;
- distinguish scientific fact, interpretation, analogy, and promotional framing;
- adapt depth and vocabulary to the audience;
- verify names, dates, numbers, links, permissions, and embargoes;
- define who approves publication.

**Typical closure:** audience-ready communication approved for the intended channel.

## Operations

**Use for:** recurring workflows, monitoring, triage, maintenance, scheduled reporting, continuity.

**Characteristic flow:**

```text
current state → signals → triage → action → monitor → adapt
```

**Required practices:**

- define cadence, ownership, and service boundaries;
- track exceptions and escalation;
- avoid silent automation expansion;
- preserve audit trail;
- measure whether the process improves its target outcome.

**Typical closure:** stable operating loop with clear escalation and review.

## Synthesis

**Use for:** cross-domain decisions, reconciling agent reports, combining research and delivery, resolving or preserving disagreement.

**Characteristic flow:**

```text
workstream returns → comparison → contradiction map → decision model → recommendation
```

**Required practices:**

- compare methods and evidence, not just conclusions;
- preserve minority findings;
- identify shared assumptions;
- state what would change the recommendation;
- avoid averaging incompatible claims.

**Typical closure:** coherent decision brief, integrated model, or prioritized next action.
